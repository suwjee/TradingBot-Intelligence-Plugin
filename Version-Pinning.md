# Version pinning

`vault_cli.py verify --mode knowledge` checks the knowledge package without reading RAW bytes; it reports `data_status=NOT_RUN` and `inventory_complete=null`, so it cannot prove data integrity. `vault_cli.py verify --mode full-data` is the default and checks the retained RAW bytes and exact windows as well.

`vault_cli.py verify` checks the Vault-local source manifest, indexed note metadata and relations, all nine main Engine snapshots, the pinned optional-reference registry, retained physical RAWs, exact windows, and unregistered physical RAW inventory. A malformed retained RAW window is reported as a verification failure. `verified_pins_ok` covers registered evidence; `inventory_complete` also requires no unregistered RAW files or sidecars. Overall `ok` and the CLI exit code require both. The Vault's `_SCHEMA/build_indexes.py --check` additionally validates schemas, relations, and derived indexes. A maintainer post-commit synchronization captures exact working-tree bytes only for clean, tracked project paths listed in the manifest and clean tracked HPZR6 references registered by repository-relative path. Dirty or untracked paths remain untouched and are reported for review; source changes update hashes but cannot automatically approve a trading rule. An index-build failure rolls back source, reference-registry, and index writes. GitHub publication is a separate action.
